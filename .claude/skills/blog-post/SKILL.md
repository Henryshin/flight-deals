# 네이버 블로그 글쓰기

`docs/data/` 의 항공권 데이터로 네이버 블로그 글 한 편을 쓴다.
**글은 매번 사람이 명령할 때 새로 쓴다.** 템플릿을 기계적으로 채우지 않는다.

목표는 "정보성 특가 안내"가 아니라 **읽는 사람이 가고 싶어지는 여행 글**이다.
가격은 글의 주인공이 아니라, 지금 움직여야 할 이유다.

## 절차

### 1. 소재 정하기

사용자가 노선을 지정했으면 그걸로 간다. 안 정했으면 후보를 뽑아 물어본다.

```bash
python scripts/blog_brief.py --stdout          # 오늘의 후보 8건
```

**브리핑 점수 1위가 가장 싼 것은 아니다.** 점수는 '평시대비 할인율'을 크게 반영하는데,
추석·성탄절은 평시 자체가 비싸서 할인율이 부풀려진다 (2026-09-11: 1위 오사카 33만원 아래에
25~28만원대가 깔려 있었다). 후보표를 만들기 전에 **절대가격으로 다시 줄 세우고**,
원장(`posts/_ledger.json`)에 있는 목적지를 빼고, 최근 관측 추이까지 본다.

### 2. 자료 읽기

```bash
python scripts/blog_brief.py --material ICN-KMI --window 2026-09-24
```

**이 출력에 있는 숫자만 쓴다.** 없는 값은 지어내지 않는다. 저장 스크립트가
본문의 금액을 자료와 대조해서, 근거 없는 숫자가 있으면 저장을 거부한다.

자료가 명시적으로 금지하는 것들:
- "항공사별 가격" 표가 비어 있으면 → 비교 표를 넣지 않는다
- 주간 비교 관측이 부족하면 → "내렸다/떨어졌다"를 쓰지 않는다
- destmeta 에 기후가 없으면 → 날씨 이야기를 쓰지 않는다

### 3. 초안 쓰기

`/tmp` 나 스크래치패드에 `draft.md` 로 쓴다. 저장소에 두지 않는다.

### 4. 검사 → 저장

```bash
python scripts/blog_save.py draft.md --dry-run   # 검증 + 평문 미리보기
python scripts/blog_save.py draft.md             # 저장 + 카드 PNG 렌더
```

저장하면 `posts/<날짜>-<노선>-<연휴>/` 에 `post.json` · `body.html` ·
`body.txt` · `images/*.png` 가 생긴다.

**발행은 이 저장소가 하지 않는다.** 검증된 별도 도구
(`98.네이버블로그자동화_v1.0/post.py`)가 담당한다. 연결 방법은
`publisher/README.md` 참고. 네이버 자동화 코드를 여기에 새로 만들지 말 것.

## 글의 구조

실제로 잘 읽히는 네이버 항공권 글의 뼈대다. 순서는 지키되, 매번 같은 문장을
쓰지 않는다.

1. **인사 + 도입** — 왜 오늘 이 목적지인가. 2~3문단.
2. **핵심 요약** — 얼마에, 어떤 조건으로 갈 수 있는지 한 덩어리. 숫자는 볼드.
3. `[[CARD:price]]` — 가격 요약 카드
4. **`## 이번 최저가 노선`** — 항공편 상세. `>` 인용 블록으로 박스처럼.
5. `[[PHOTO: ...]]` — 목적지 사진 자리
6. **`## 항공사별 가격 비교`** — 표. 자료에 2개 이상 있을 때만.
   `[[CARD:airlines]]` 를 대신 써도 된다.
7. **연차 이야기** — `[[CARD:schedule]]` 로 어느 날이 공휴일·주말·연차인지
   한눈에 보여준다. 연차가 많이 드는 일정일수록 이걸 먼저 보여주는 게 낫다.
   **`다른 일정 후보` 표는 넣지 않는다** (사용자 지정 2026-09-08 — 혼선을 준다).
8. **가격 추이** — `[[CARD:trend]]` + 짧은 해석. 선택. 소제목은 붙여도 되고
   안 붙여도 된다 (`가격이 어떻게 움직였나` 처럼 앞 내용을 되풀이하는 제목은 뺀다).
9. **`## {도시}에서는 뭘 하면 좋을까`** — 여행 파트. 기후·계절 근거를 깔고
   구체적인 장면으로. `[[PHOTO: ...]]` 두어 곳.
10. **마무리** — 가격 변동 고지 + 대시보드 링크.
    끝에 `지금 가기 좋은 이유` 같은 **요약 블록은 넣지 않는다** — 앞에서 이미 말한
    숫자를 되풀이해서 발행 때 지워진다 (2026-09-08 실측).

### 사진 고르는 기준

`[[PHOTO: 설명]]` 은 사진이 들어갈 자리다. **최소 2곳**은 둔다.

눈대중으로 고르면 매번 결과가 달라진다. 순서대로 거른다.

**0단계 — 어느 장소를 넣을지부터 정한다.**
`python publisher/photo_pick.py --places "Jiufen" "Yehliu" "Taipei 101"`

**커먼즈에 그 장소 사진이 몇 장 있는지**로 줄을 세운다. 사람이 많이 가고 찍을 만한
곳일수록 사진이 쌓이므로 인기의 대리지표가 되고, 동시에 내가 고를 재고와 같은 값이다.
실측 예: 타이베이101 3,103 · 지우펀 1,340 · 예류 537 · 잔교 73.

**반드시 정확구(따옴표)로 센다.** 안 그러면 `Victoria Peak` 이 두 단어로 흩어져
28만 건으로 나온다 (정확구로는 1,646건).

다른 지표도 재 봤지만 우리 목적엔 안 맞았다 (2026-09-09):

| 후보 | 실측 | 왜 안 되나 |
|---|---|---|
| 위키 사용(인용) 횟수 | 딤섬 206곳 / 좋은 풍경 사진 0곳 | 사진의 매력이 아니라 '그 사진이 들어갈 문서가 있나'를 잰다 |
| 위키백과 조회수 | 지우펀 143회 | 백과사전 조회는 여행 욕구와 별개다 |

**1단계 — 기계로 거른다.** `python publisher/photo_pick.py "<검색어>"`

커먼즈 품질 등급을 1차 필터로 쓴다. 커뮤니티가 이미 심사해 둔 것이라
내 취향보다 믿을 만하다.

| 등급 | 뜻 |
|---|---|
| ★★★ Featured pictures | 투표로 뽑은 최상위 |
| ★★ Quality images | 기술 품질 심사 통과 |
| ★ Valued images | 그 주제에서 가장 가치 있는 사진 |

여기에 가로 사진 · 최소 2000px · 허용 라이선스를 같이 건다.

**2단계 — 썸네일을 실제로 보고 판단한다.** 등급이 여행 사진으로서의 매력까지
보장하지는 않는다 (칭다오 ★★ 중 하나는 고가도로 차량 정체 사진이었다).

- **인물 크기** — 얼굴·상반신이 식별되면 탈락. 멀리 작게 찍힌 사람은 괜찮다
- **빛** — 골든아워·야간 조명 > 맑은 낮 > 흐린 낮. 회색 평면 조명은 거른다
- **깊이** — 전경·중경·원경이 겹치는 구도를 고른다.
  (소나무 가지 → 흰 바위 → 청록 바다처럼 겹이 있는 쪽이 훨씬 낫다)
- **계절 일치** — 글의 여행 월과 사진의 계절이 맞아야 한다.
  10월 글에 앙상한 겨울나무 사진을 넣지 않는다
- **장소 특정성** — 어디인지 읽히는 사진. 어디서나 찍힐 법한 것은 약하다
- 같은 랜드마크를 한 글에 두 번 넣지 않는다

**3단계 — 소재가 없으면 목적지를 의심한다.** 목적지마다 커먼즈 사진의 양이
크게 다르다 (2026-09-09 실측: 홍콩 340건 · 타이페이 302건 · **칭다오 3건**).
등급 있는 게 한 자릿수면 그 글은 사진이 약해질 수밖에 없다.
**후보를 검토받을 때 이 숫자를 같이 알린다.**
여행 사진은 저작권 때문에 자동으로 못 넣는다 — 초안에 자리만 잡아 두고,
사용자가 임시저장 글에 본인 사진을 얹은 뒤 발행한다.

## 문체

**짧게 끊어 쓴다.** 한 문단은 2~3줄. 줄바꿈 자체가 스타일이다.
모바일에서 읽히는 글이라 긴 문장은 그냥 안 읽힌다.

```
아시아나 직항 기준으로
왕복 18만원대부터 예약 가능하더라고요.

위탁수하물 23kg도 포함된 가격이에요!
```

- 종결어미: `~하더라고요`, `~이에요`, `~같아요`, `~거든요`, `~드려요`
  — 딱딱한 `~합니다`체는 쓰지 않는다
- `ㅎㅎ`, `:)` 정도는 자연스럽게. 남발하지 않는다
- 핵심 숫자·조건은 `**볼드**`
- 첫 문단에 가격을 던지지 않는다. 먼저 왜 이 목적지인지를 말한다
- 여행 파트는 감각적으로 — 소리, 온도, 아침의 빛. 다만 **기후 자료를 벗어나지
  않는다**. 우기인 달에 "건조하다"고 쓰면 저장이 거부된다

**쓰지 않는 말**: 강추, 역대급, 무조건, 대박, 실화, 미쳤다, 레전드.
검증에서 걸린다. 과장 없이 구체적인 사실로 설득한다.

### 제목 — 검색어가 앞에 온다

**`{도시} 항공권 {가격}대, {연휴} {직항} 특가`** 가 기본이다. 45자 이내, 낚시성 표현 금지.

```
칭다오 항공권 26만원대, 개천절 직항 특가
홍콩 항공권 29만원대, 개천절 직항 특가
```

연휴명을 앞에 두지 않는다 (`개천절 코타키나발루, …` ✗). "코타키나발루 항공권"은 자동완성에
실재하는 검색 조합이고 "개천절 코타키나발루"는 아니다. 연휴는 뒤에 붙는 수식이다
(SEO 처방 2026-09-10).

### 태그 — 자동완성에 실재하는 조합만

3~10개. `#` 없이, 공백 없이.

```
tags: [칭다오항공권, 칭다오여행, 칭다오직항, 칭다오10월날씨, 칭다오자유여행, 중국여행]
```

| 넣는다 | 빼는다 |
|---|---|
| `{도시}항공권` `{도시}여행` `{도시}직항` | `{연휴}연휴` — 검색 유입이 없다 |
| `{도시}{여행월}월날씨` — 경쟁 낮은 실수요 | `인천{도시}` — 아무도 그렇게 안 찾는다 |
| `{도시}자유여행` `{나라}여행` | 연휴명 단독 (`부처님오신날`) |

### 곁가지 키워드 섹션

항공권 글 안에 **날씨·입국 정보 문단**을 붙인다. 신규 블로그가 첫 유입을 만드는
현실적인 경로는 "{도시} {월} 날씨" 같은 경쟁 낮은 실수요 키워드다.

- 날씨 소제목은 **검색어 그대로**: `## 칭다오 10월 날씨` (`## 10월 칭다오 날씨는 알고 가세요` ✗)
- 입국 정보(무비자 기간 등)는 **확인한 것만** 쓰고 "출발 전 한 번 더 확인" 을 붙인다
- 환율은 숫자를 박지 않는다 — 발행 직후 틀린다. 통화 이름과 환전 요령 정도만

### 표기 통일

제목·태그·본문의 도시 표기를 하나로 맞춘다. 자동완성 기준으로 **타이페이**(타이베이 ✗).
`data/routes.json` 의 라벨과 태그가 갈리면 태그를 라벨에 맞춘다.

### 여행일이 너무 멀면 쓰지 않는다

출발까지 **120일**을 넘는 연휴는 후보에서 빠진다 (`blog/brief.py` `MAX_LEAD_DAYS`).
수요는 여행 두어 달 전에 생긴다. 8개월 뒤 5월 연휴 글을 9월에 올리면 3월까지
아무도 안 찾는다.

### 왕복 항공사는 반드시 특정한다

**가는 편·오는 편 항공사가 둘 다 채워져야 저장된다.** 하나라도 비었거나 '미상'이면
`blog_save.py` 가 거부한다 (사용자 지정 2026-09-09).

최저가는 두 편의 항공사가 다른 **다구간 항공권**인 경우가 흔하다. 한쪽만 적으면
사실과 달라지고, '미상'인 채로 나가면 글의 신뢰가 깎인다.

수집기가 못 채웠으면 **구글 항공권을 직접 열어 확인**하고 머리말에 넣는다.

```
airline: 홍콩 익스프레스항공
ret_airline: 홍콩 익스프레스항공
ret_dep_time: '00:50'
ret_arr_time: '05:30'
```

### 할인율은 "같은 일정 2위 항공권 대비"다

**할인율 = (2위 가격 − 이 항공권 가격) ÷ 2위 가격.**
2위 = 같은 출발·귀국일 **직항** 중 **최저가와 다른 항공사**의 최저가. 경유편은 넣지 않는다.
사용자 확정 정의다 (2026-09-14). 9/13 의 "나머지 직항 중앙값 대비"는 숫자가 너무 커 보인다고
반려됐다 (호치민 12/19~27: 중앙값 대비 50.8% → 2위 에어프레미아 대비 21.7%).

- 같은 항공사의 다른 시간대 편은 2위로 치지 않는다. 대개 같은 운임이라 0%가 된다
  (호치민: 비엣젯 10:50·21:15 둘 다 350,257원).
- 예전 `deal_pct`(연휴 전체 관측가 중앙값 대비)로 "특가"·"N% 싸다"를 쓰지 않는다.
- 수집기가 2026-09-14 부터 직항 행에 `runnerup_price` · `runnerup_airline` 을 남긴다.
  그 전 수집분에는 없어서 브리핑이 "통계 없음"으로 표시한다 (옛 중앙값으로 대신 채우지 않는다).
- 통계가 없으면 구글 항공권 같은 일정 직항 목록에서 2위를 **직접 확인해** 머리말에 넣는다.
  가격 카드 배지가 "같은 날짜 직항 2위 ○○항공 ○원보다 N% 낮아요"로 나간다.

```
runnerup_price: 447200
runnerup_airline: 에어프레미아
```

- **수하물 조건이 다르면 본문에 함께 밝힌다.** 저비용항공 최저가(위탁 유료) vs 2위 위탁 포함이면
  할인율만 보고 "싸다"로 끝내지 않는다.
- 같은 편이 화면에 li 두 개로 잡힌다. (항공사, 출발시각, 가격)으로 중복을 뺀다.

### 가격은 발행 전에 실조회로 맞춘다

수집기는 4시간마다 돌지만 **(노선 × 일정) 조합을 매번 다 훑지는 못한다.** 인기 구간은
하루 이틀 전 값이 남아 있고, 그 사이 실제 가격이 크게 움직이기도 한다
(2026-09-11 괌 한글날: 수집 286,588원 · 실제 305,931원. 같은 에어서울 편이 하루 만에
286,290 → 381,277 로 튄 것도 관측됐다).

**후보를 고른 뒤 구글 항공권을 직접 열어** 가격 · 오는 편 시각 · 양쪽 항공사를 확인한다.
확인한 값은 머리말로 넘긴다.

```
price: 305931
price_checked_at: '2026년 9월 11일 15:00'
```

이 값은 카드 히어로 숫자와 할인율, 그리고 본문 금액 검증(`known_prices`)에 그대로 반영되고,
카드 하단 고지가 "구글 항공권에서 **직접 조회한 값**"으로 바뀐다. 즉 자료 대조를 건너뛰는 게
아니라 **대조 기준 자체를 실측값으로 바꾸는** 필드다. 그래서 조회 화면을 보지 않고 쓰면 안 된다.

빈칸이 나오는 흔한 원인은 크롤러 사전에 그 항공사 표기가 없는 것이다
(2026-09-09: '스쿠트'만 있고 '스쿳항공'이 없어 타이페이 관측의 51%가 미상이었다).
새 이름을 확인했으면 `collector/google_flights_crawler.py` 의 `AIRLINES` 에
**구글이 쓰는 철자 그대로** 추가하고, 블로그 표기가 다르면 `AIRLINE_CANON` 으로 옮긴다.

머리말 `itinerary:` 는 **어느 일정을 주인공으로 삼을지**다. 본문 숫자와 카드가 같이
이걸 따라가므로 둘이 어긋나지 않는다. 생략하면 `auto`.

| 값 | 고르는 것 |
|---|---|
| `auto` (기본) | 가격과 **연차 부담**을 함께 본 점수. 대개 이게 맞다 |
| `cheapest` | 최저가. 연차가 많이 들어도 무조건 싼 것 |
| `min_leave` | 연차가 가장 적은 것. 값이 확 뛸 수 있으니 확인하고 쓴다 |
| `2026-09-25:2026-09-28` | 출발:귀국 직접 지정. 자료에 없으면 저장이 거부된다 |

**연차가 4일 넘게 드는 일정은 웬만하면 쓰지 않는다** (사용자 지정 2026-09-08 —
"일정 너무 길다"). 후보 점수에도 연차 부담이 들어가 있어서 브리핑 상위가 이미
짧은 쪽으로 기운다.

빈 줄이 문단 구분. 문단 안의 줄바꿈은 그대로 살아난다.

## 하지 않는 것

- **발행하지 않는다.** 임시저장까지가 자동화의 끝이고, 발행 버튼은 사용자가 누른다.
- 자료에 없는 숫자를 쓰지 않는다.
- 여행 사진을 임의로 가져오지 않는다. `[[PHOTO:]]` 자리만 잡는다.
- 제휴 링크를 넣지 않는다 (이 블로그는 제휴를 쓰지 않기로 했다).
  링크는 대시보드와 예약 링크 정도로 최소한만.
