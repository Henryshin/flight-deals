2번이 끝나면 **예약 시각을 잡고 발행 버튼을 누르는 것만** 남는다. 그건 사람이 한다.

`photos.json` 은 있는데 사진을 아직 안 받았으면 **2번이 알아서 받는다.** `fetch_photos.py` 를
따로 돌릴 필요가 없다(받는 것은 에디터를 건드리기 전에 끝낸다). 따로 돌리고 싶으면
`python publisher\fetch_photos.py posts\<슬러그>`, 안 받게 하려면 `--no-fetch`.

**`photos.json` 을 만드는 것은 자동화 대상이 아니다** — 커먼즈에서 후보를 검색하고 썸네일을
눈으로 보고 고르는 일이다. 그건 Claude 가 한다. 사용자 손이 가는 명령은 1번과 2번 둘뿐이다.

`--fresh` 는 글쓰기 화면을 새로 열어 빈 글에서 시작한다(쓰던 내용은 버려진다).
찾은 탭이 글쓰기 화면이 아니면 그 탭을 건드리지 않고 새 탭에서 연다.

## 1. 하지 말 것

| | 왜 |
|---|---|
| `browser.close()` | 연결 해제가 아니라 **사용자 크롬이 진짜로 닫힌다.** `with` 블록만 빠져나온다 |
| 최종 발행 버튼 클릭 | `confirm_btn__*` 이 진짜 발행이다. **누르지 않는다.** 예약·발행은 사람 몫 |
| 사용자 탭 재사용 | 발행글 수정 중인 탭을 `--fresh` 로 이동시키면 그 작업이 날아간다 |
| 아무 데서나 가져온 사진 | 라이선스 확인된 커먼즈 사진만. 출처 문단은 지우지 않는다 |
| 본문 숫자 수정 | 모든 금액은 수집 데이터와 대조를 통과한 값이다 (`scripts/blog_save.py` 가 강제) |

글 내용을 고칠 일이 생기면 초안을 고쳐 `python scripts/blog_save.py <draft.md>` 로 다시 저장한다.
`post.json` 을 직접 만지지 않는다.

## 2. 실물에서 깨졌던 것 — 다시 발견하느라 시간 쓰지 말 것

전부 가짜 에디터로는 안 보이던 것들이다.

### 2-1. 에디터는 iframe 안이다
`page.frame(name="mainFrame")`. 최상위 page 에서 찾으면 전부 빈 결과.

### 2-2. 탭을 URL 부분일치로 고르면 안 된다
네이버 **로그인 페이지의 `url=` 파라미터에 `blog.naver.com` 이 그대로** 들어 있어서
`"blog.naver.com" in page.url` 이 로그인 탭에 먼저 걸린다. 첫 실행이 여기서 죽었다.

그리고 제목칸(`.se-title-text`)만 봐도 안 된다 — **발행된 글을 읽는 화면에도 같은 클래스가 있다.**
편집 화면에만 있는 툴바(`.se-image-toolbar-button`)까지 봐야 갈린다.

### 2-3. 본문 컨테이너를 `.se-component-content` 로 잡으면 안 된다
이 클래스는 **제목 컴포넌트에도 있다.** 빈 글에서도 2개가 잡힌다.
- `querySelector` 첫 매치가 제목이라 캐럿이 제목칸으로 간다
- `locator(...).inner_text()` 는 매치가 여러 개라 strict mode 위반으로 죽는다

→ 본문은 `.se-component.se-text` 로 스코프한다.

### 2-4. Selection API 로 캐럿을 옮길 수 없다
본문 문단에 **`contenteditable` 조상이 아예 없다** (`closest('[contenteditable=true]')` → `null`).
에디터가 숨은 input buffer 로 입력을 받아 자기 캐럿 모델을 따로 굴린다. `<p>.focus()` 는 무효라
`document.getSelection()` 을 옮겨도 에디터가 안 따라온다.

캐럿을 옮기는 방법은 **마지막 문단을 클릭하는 것**뿐이다. 이 스크립트가 캐럿을 옮기는 시점
(이미지 앞뒤)의 마지막 문단은 항상 비어 있어서 클릭만으로 끝에 놓인다.

- `End` 키 — 문단 끝이 아니라 **화면 줄 끝**으로 간다. 거기서 이미지를 넣으면 문장이 두 동강 난다
- `Ctrl+End` — 이 에디터에서 동작하지 않는다
- 트리플클릭 — 문단을 '선택'하는 연산이라 collapse 전에 `insert_text` 가 들어가면 통째로 덮어쓴다

### 2-5. 줄이 조용히 사라진다 ★
`insert_text` 직후 `Enter` 를 바로 치면 에디터가 아직 입력을 처리하는 중이라 **줄이 통째로 씹힌다.**
30줄 블록에서 5줄, 18줄 블록에서 5줄이 유실됐다.

더 나쁜 건 **블록 단위 대조가 마지막 줄만 확인해서 그대로 통과**했다는 것이다. 맨 끝
전체 대조에서야 걸렸다.

→ 줄마다 마지막 문단을 읽어 대조하고, 비어 있으면 다시 넣는다. `Enter` 도 같은 방식으로 확인한다.

### 2-6. `insert_text` 는 실패해도 예외를 안 던진다
넣고 나서 읽어 대조하지 않으면 **제목이 통째로 빈 글이 조용히 발행까지 간다.** 실제로 겪은 일이다.

### 2-7. 새 문단은 `insert_text`, 기존 문단 교체는 `type`
`type()` 으로 `"1. 개요"` 처럼 숫자+마침표로 시작하는 줄을 치면 **자동 번호매기기가 발동**해
그 줄부터 끝까지 순서 목록이 된다. 반대로 `insert_text` 는 선택 영역을 안 지워서 교체엔 못 쓴다.

### 2-8. 빈 문단에 플레이스홀더 span 이 실제로 들어 있다
`글감과 함께 나의 일상을 기록해보세요!` 가 `.se-placeholder` 노드로 DOM 에 있다.
그냥 읽으면 본문 텍스트로 섞인다. → 대조 전에 걷어낸다.

### 2-9. 오른쪽 사이드바가 클릭을 가로챈다
`.se-sidebar-interaction` 이 문단 오른쪽 끝을 덮는다. 이미 넣은 문단을 **범위 선택해서** 서식을
바꾸려다 여기서 죽었다.

→ 선택하지 말고 **빈 문단에 서식을 먼저 걸고 쓴다.** 정렬·글자 크기는 '현재 서식'으로 이어진다.

### 2-10. 복구 대화상자
`text=취소` 는 화면에 안 보이는 스크린리더용 span 을 먼저 잡아 타임아웃된다.
→ `.se-popup-alert-confirm button:has-text('취소')`

닫힌 걸 확인하지 않고 진행하면 **이전 초안 위에 덮어쓴다.** 입력 전에 빈 글인지 확인한다
(빈 글 기준: 제목 `제목`, 본문 문단 1개, 이미지 0개).

### 2-11. 에디터 안에서 링크는 `<a>` 가 아니다 ★
글자에 링크를 걸면 **`<a>` 가 아니라 `span.se-link` 의 `data-href`** 로 들어간다.
`<a>` 는 발행된 뒤에야 생긴다. `document.querySelectorAll('a')` 로 확인하면 멀쩡히 걸린 링크를
'안 걸렸다'고 오판한다 — 그것 때문에 같은 링크를 네 번 다시 걸었다.

```js
Array.from(document.querySelectorAll('span.se-link'))
     .some(s => (s.getAttribute('data-href')||'').includes(url))
```

링크 버튼은 두 개다. `se-oglink-toolbar-button`("링크 추가")은 **카드 컴포넌트**를 넣는 것이고,
글자에 링크를 거는 것은 `se-link-toolbar-button`("링크 입력")이다.

선택은 **트리플클릭**으로 한다. `Shift+Home` 으로는 선택이 안 잡혔다. 여기서 트리플클릭은
맞는 용법이다 — 선택에 링크를 거는 것이고 뒤에 `insert_text` 를 하지 않아 덮어쓸 위험이 없다.

확정 버튼(`se-custom-layer-link-apply-button`)은 오른쪽 **사이드바 패널 헤더에 가려** 클릭이
가로채이는 경우가 있다. Enter 로 먼저 시도하고, 안 되면 히트테스트를 건너뛰는 JS 클릭으로 누른다.

### 2-12. 글감 검색 패널이 본문 클릭을 전부 가로챈다
링크 레이어에는 입력칸이 **두 개**다. URL 칸은 `input.se-custom-layer-link-input`(placeholder
"URL을 입력하세요.")이고, 다른 하나는 글감 검색칸(`se-flayer-unified-search-input`)이다.
`input[type='text']` 로 뭉뚱그려 잡으면 글감칸에 URL 이 들어가고, **검색 결과 패널이 열려
본문 클릭을 전부 가로챈다.**

이 패널은 **Escape 로 안 닫힌다.** 전용 닫기 버튼 `.se-flayer-unified-result-close` 만 먹는다.

### 2-13. `html_to_paragraphs` 는 `<a>` 도 지운다 — 지금은 그게 맞다
`re.sub(r"<[^>]+>", "", s)` 가 태그를 전부 지우므로 원문의 링크가 평문이 된다.
2026-09-08 첫 발행글은 이것 때문에 **링크가 하나도 없는 채로** 올라갔다.

고친 방식은 "원문 `<a>` 를 되살리기"가 아니다. **본문에 거는 링크는 `booking_url` 하나로 정했다**
(6-1 참조). 원문 안의 자체 사이트 링크(`excel-flights.xyz`)는 **넣지 않는 것이 맞다** — 사용자가
그렇게 결정했다.

무엇이 평문으로 갔는지는 로그에 남지만 **결함이 아니다.**
`원문 <a> 는 평문으로 둠(의도)` 로그를 보고 "링크가 빠졌다"며 되살리지 말 것.

### 2-14. 팝업이 툴바를 덮는 일이 있다
한 번 `.se-popup-alert` 가 사진 버튼 클릭을 30초 재시도하다 죽였다. **재현되지 않았고 원인 미상.**
지금은 팝업 문구를 에러에 실어 주므로, 또 나면 그 로그를 보고 판단한다.

## 4. 서식 규칙

- **본문은 항상 가운데정렬.** `ALIGN_DEFAULT = "center"`
  문단마다 걸지 않고 **다 채운 뒤 전체 선택해서 한 번만** 누른다. 정렬이 '현재 서식'으로
  이어지는 성질 때문에 중간에 걸면 이후 입력·이미지 삽입과 얽힌다.
  누른 뒤 **전체 선택을 반드시 푼다** — 남겨 두면 다음 입력이 문서를 통째로 덮어쓴다.
- **사진 출처만 왼쪽 · 11pt**(최소 크기). 본문 정렬을 끝낸 뒤에 붙인다. 순서를 바꾸면
  전체 선택 가운데정렬이 출처 서식까지 덮어쓴다.

> 주식리서치 보고서 쪽 README 에 "정렬이 문서 전체로 번져 사고가 났다"는 기록이 있는데,
> **그건 그 글에 해당하는 이슈다.** 그 글은 캡션만 가운데고 본문은 왼쪽이라 번짐이 문제였다.
> 항공권 블로그 글은 어차피 전부 가운데라 그 성질이 오히려 도움이 된다.

## 5. 사진

여행 사진은 **위키미디어 커먼즈에서 라이선스를 확인한 것만** 쓴다.

1. 후보를 커먼즈 API 로 검색하고 **썸네일을 실제로 눈으로 보고** 고른다
2. 고른 결과를 `posts/<슬러그>/photos.json` 에 적는다
   ```json
   [{"hint": "post.json 의 photo 자리 설명 그대로",
     "commons": "File:....jpg",
     "file": "images/photo-1-....jpg"}]
   ```
   `hint` 는 `post.json` 의 photo 블록과 **문자열이 정확히 같아야** 짝이 맞는다.
3. `fetch_photos.py` 가 라이선스를 허용 목록(CC BY / CC BY-SA / CC0 / PD)과 대조한다.
   목록에 없으면 받지 않고 그 자리에서 죽는다. 원본이 4~6천 픽셀이라 1600px 비례 축소본을 받는다.
4. `photo-credits.json` 이 남고, `post_to_naver.py` 가 그걸 보고 사진을 넣은 뒤
   **글 끝에 출처 문단을 붙인다.**

**출처 문단은 지우면 안 된다.** CC BY / BY-SA 의 저작자 표시 의무다.

초안 단계 규칙은 그대로다 — 글 쓸 때는 `[[PHOTO: 설명]]` 자리만 잡고 사진을 끌어오지 않는다.

## 6. 태그

`post.json` 의 `tags` 를 발행 설정 패널에서 자동 입력한다. 넣은 뒤 `aria-label` 로 전부 들어갔는지
확인하고, 하나라도 빠지면 멈춘다. **패널만 열고 발행은 하지 않는다.**

넣고 싶지 않으면 `--no-tags`.

이미 발행된 글에 태그를 넣으려면 수정 화면으로 들어가야 한다. 발행글 화면의 수정 링크는
`javascript:suggestConvert(<logNo>, true, false, 4)` 이고, 같은 텍스트의 숨은 링크가 여러 개라
보이는 것만 골라야 한다.

---

## 6-1. 링크 — 본문에 거는 것은 하나뿐

`post.json` 의 `booking_url`(그 조건이 조회되는 **구글 항공권 화면**)을 본문 맨 끝
`구글 항공권에서 이 조건 그대로 보기` 문구에 건다. **글에서 제일 중요한 링크다.**

그 외에는 걸지 않는다. 원문 HTML 안의 자체 사이트 링크(`excel-flights.xyz`)는 평문으로 둔다 —
사용자 결정(2026-09-08)이며 의도된 동작이다. `다른 노선이랑 연휴별 가격은 여기에...` 문장의
"여기"에 링크가 없는 것도 그래서다.

## 7. 아직 사람이 하는 것

- **가독성용 빈 줄.** 2026-09-08 발행 때 사용자가 **폭 없는 공백(U+200B) 문단 23개**를 손으로
  넣었다. 원문 HTML 의 `<p>` 경계는 51곳인데 23곳만 골랐다 — 사진 앞뒤에는 항상, 나머지는
  의미 덩어리 사이에. 소제목과 바로 뒤 내용은 붙여 뒀다. **규칙으로 못 뽑았다.** 자동화하려면
  간격을 원문(`post.json`)에 적어 두는 쪽이 맞다.
- **내용 편집.** 같은 날 8줄을 지웠다 (`가격이 어떻게 움직였나` 소제목, 마무리 `정리하면` 요약
  블록 7줄). 앞에서 이미 말한 숫자를 반복하던 것들이다.
  → **`post.json` 은 아직 이 편집을 모른다.** 그대로 다시 돌리면 지운 줄이 되살아난다.
- 예약 시각 지정과 최종 발행 클릭.
